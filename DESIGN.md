# DESIGN

## 1. Структуры данных

В проекте используются следующие основные структуры данных:

### GameSettings

Содержит настройки новой игры:

- `length` — длина секретного числа;
- `base` — основание системы счисления.

### GameState

Хранит текущее состояние игры:

- `settings` — настройки;
- `status` — статус игры (`setup`, `playing`, `won`);
- `secret` — загаданное число;
- `history` — история попыток;
- `startedAt` — время начала игры;
- `finishedAt` — время завершения игры.

### GuessEntry

Представляет одну попытку:

- `guess` — введённое число;
- `bulls` — количество цифр на правильных позициях;
- `cows` — количество правильных цифр на неправильных позициях.

### GameRecord

Хранит результат завершённой игры:

- `settings` — использованные настройки;
- `attempts` — количество попыток;
- `duration` — продолжительность игры в миллисекундах;
- `achievedAt` — время завершения игры.

### Дополнительные структуры данных

- `Array` используется для хранения цифр, истории попыток и рекордов.
- `Set` используется для проверки уникальности цифр.
- `Map` используется для кеширования результатов подсчёта возможных секретных чисел.
- `localStorage` используется для сохранения рекордов между сеансами приложения.

## 2. Алгоритмы

### generateSecret

Функция генерирует секретное число заданной длины в выбранной системе счисления.

Сначала создаётся массив всех доступных цифр основания системы счисления. Затем применяется частичное перемешивание Fisher–Yates: на каждой итерации случайным образом выбирается одна из ещё не выбранных позиций, после чего цифры меняются местами.

В результате выбираются уникальные цифры без повторений.

### evaluateGuess

Функция сравнивает секретное число с попыткой пользователя.

- **Бык** — цифра совпадает с секретной и находится на правильной позиции.
- **Корова** — цифра присутствует в секрете, но находится на другой позиции.

Сравнение выполняется без учёта регистра.

### isValidGuess

Функция проверяет корректность попытки:

1. Длина числа должна совпадать с заданной.
2. Все символы должны быть допустимыми цифрами выбранной системы счисления.
3. Цифры не должны повторяться.

Для проверки допустимости цифр используется `createDigitValidator`, для проверки уникальности — `Set`.

### countPossibleSecrets

Функция вычисляет количество возможных секретных чисел для заданной длины и основания системы счисления.

Используется рекурсивная формула:

`P(base, length) = (base - length + 1) * P(base, length - 1)`

Базовые случаи:

- при длине `0` результат равен `1`;
- если длина превышает основание системы счисления, результат равен `0`.

Для ускорения повторных вычислений используется мемоизация с помощью `Map`.

## 3. Оценка сложности алгоритмов (Big O)

Обозначения:

- `n` — длина секретного числа;
- `b` — основание системы счисления.

| Функция                | Временная сложность | Пространственная сложность |
| ---------------------- | ------------------- | -------------------------- |
| `generateSecret`       | O(b + n)            | O(b)                       |
| `evaluateGuess`        | O(n²)               | O(n)                       |
| `isValidGuess`         | O(n)                | O(n)                       |
| `countPossibleSecrets` | O(n)                | O(n)                       |

### Пояснения

**generateSecret**

Создание массива цифр требует O(b). Частичное перемешивание выполняет `n` итераций. Общая временная сложность — O(b + n), дополнительная память — O(b).

**evaluateGuess**

Сравнение выполняется в несколько проходов по строкам. Для каждой цифры во втором проходе может выполняться поиск через `includes`, требующий до O(n). Поэтому общая временная сложность — O(n²). Дополнительная память — O(n).

**isValidGuess**

Проверка допустимости цифр и создание `Set` требуют линейного времени относительно длины числа. Временная и пространственная сложности — O(n).

**countPossibleSecrets**

При первом вычислении для заданной длины выполняется до `n` рекурсивных вызовов. Благодаря мемоизации ранее вычисленные результаты повторно не рассчитываются. Временная и пространственная сложности первого вычисления — O(n). Повторный вызов с уже сохранёнными параметрами выполняется за O(1).

## 4. Принципы Clean Code

В проекте применяются следующие принципы:

### Single Responsibility Principle

Функции разделены по назначению:

- `generateSecret` отвечает за генерацию числа;
- `evaluateGuess` — за подсчёт быков и коров;
- `isValidGuess` — за проверку попытки;
- `sortRecords` — за сортировку рекордов;
- `record-storage` — за работу с локальным хранилищем.

### Pure Functions

Алгоритмы генерации, сравнения и проверки отделены от интерфейса и работы с хранилищем. Это упрощает тестирование и повторное использование.

### Dependency Injection

Функции `generateSecret` и `startGame` принимают генератор случайных чисел и текущее время в качестве параметров. Это позволяет контролировать внешние зависимости в тестах.

### Immutability

При сортировке рекордов создаётся копия исходного массива. Игровое состояние также обновляется созданием новых объектов, без изменения предыдущего состояния.

### Early Return

Некорректные и повторные попытки отклоняются в начале выполнения `submitGuess`. Это уменьшает вложенность условий и упрощает чтение кода.

### Meaningful Names

Имена функций, типов и переменных отражают их назначение, например `generateSecret`, `isValidGuess`, `GameRecord` и `finishedAt`.

### Test-Driven Development

Разработка основных модулей выполнялась по циклу RED → GREEN: сначала создавались заглушки и тесты, затем реализовывалась функциональность до прохождения тестов.
